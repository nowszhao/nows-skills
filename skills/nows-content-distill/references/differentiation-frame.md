# Differentiation Frame · 差异化亮点 + 强制调研

这是整个 skill 最难、也最关键的一章。它回答的不是 "这篇说了什么"，而是 **"这篇相对于同类内容，独特贡献是什么"**。

## 一、为什么要强制调研

模型在没有外部输入时，对"该领域多数人怎么说"的判断**极不可靠**——会编造、会偏见、会用过时认知当基线。
"差异化"如果建立在编出来的"默认认知"上，整个亮点就是塑料花。

**所以：差异化亮点章节落笔前，必须完成一轮强制调研。** 这条不能跳。

## 二、强制调研的执行

### 触发时机
Step 4 写"差异化亮点"之前。

### 必做项
- 用 `web_search` 围绕**这一篇的核心议题**做至少 **3 次不同关键词** 的检索
- 找到至少 **3 个** 同生态、同类型、同主题的来源（不是"任意 3 个相关网页"）
- 用一句话总结"该议题在同生态里**多数同类内容**怎么说"——这就是**默认认知基线**

### "同生态、同类型、同主题"的判定（核心）

| 维度 | 含义 | 例子（以 Lenny's Podcast × Anthropic 工程访谈为例） |
|---|---|---|
| **同生态** | 同样的内容圈层与受众层 | a16z / Latent Space / Last Week in AI / Lenny's 自己的其他集 / All-In Pod |
| **同类型** | 访谈对访谈，博客对博客，论文对论文 | 不要拿小红书短帖、知乎随手回答、推特碎片化口水 当对照 |
| **同主题** | 围绕这一篇的**具体议题**，不是宽泛领域 | 议题应该是"AI 时代工程师的角色变化 / 验证瓶颈 / 工程文化转型"，**不是"AI"** |

**禁止当作"默认认知基线"**：

- ❌ 网络口水（"AI 让人失业"、"AI 让 X 变得更容易"、"以后不需要 X 了"）
- ❌ 短视频流行观点 / 朋友圈刻板印象
- ❌ 五年前的旧共识（AI 领域共识半衰期极短）
- ❌ 大众媒体科普文章里的笼统说法

**判定校验**：把"默认认知基线"读出来，问自己——"这话同生态的同类内容里**已经反复说过了**吗？" 答 "没有，这是大众/外行才这么说" → 调研不合格，重做。

### 检索词建议
- 话题主语（人名 / 产品名 / 概念名） + 领域词 + 时间窗（限定到近 1 年）
- 同生态平台名 + 议题（如 `Lenny's Podcast AI engineering bottleneck`、`a16z coding solved`）
- 议题的反面（如本篇说"coding is no longer the bottleneck" → 搜 `coding bottleneck AI 2025`）
- 英文 query 和中文 query 各做一轮（中英文社区共识可能完全不同）

### 留痕（必须）

写入 MD 末尾的 `## 调研记录` 段落（HTML 不渲染，仅 MD 保留）：

```markdown
## 调研记录
- 检索词：…… / …… / ……
- 同生态来源：[标题](URL) / [标题](URL) / [标题](URL)
- 默认认知基线（一句话，必须是同生态同类内容里反复出现的观点）：……
- 这一篇相对基线的真实差异（≥3 条简列）：
  1. ……
  2. ……
  3. ……
```

**留痕硬指标**：
- "同生态来源" 至少 3 条 URL，且能说清楚为什么算"同生态"
- "默认认知基线" 不能是网络口水（见上方禁止清单）
- "真实差异" 至少 3 条且**对应到原文具体表达**（最好附原文短引用）

## 三、差异化亮点的写作

### 数量
**1–3 条**。少而精。"全是亮点 = 没有亮点"。

### 每条强制三段式

```markdown
### 亮点 N：{{一句话标题，能体现差异点本身，不是"X 很重要"这种废话}}

- **同生态多数同类内容会说**：……（必须来自调研，不是猜的）
- **这一篇说**：……（原文真实表达，必须附原文短引用或转录引用）
- **为什么有价值**：……（说清差异戳到了哪个普遍误区 / 暴露了哪个被忽视的机制 / 提出了哪个新视角）
```

三段必须严格对应：
- "同生态多数同类内容会说" 来自调研，**不能是网络口水**（见前文禁止清单）
- "这一篇说" 必须**对应到原文一个具体段落或具体引用**——空洞的"作者认为 X" 不算
- "为什么有价值" 不是赞美，是说清"这个差异戳到了哪个普遍误区 / 暴露了哪个被忽视的机制 / 提出了哪个新视角"

### 价值类型（用来检验是不是真亮点）

差异要落到下面至少一种类型，否则它就不是亮点：

| 类型 | 判定 |
|---|---|
| **反共识** | 多数人认为 A，作者论证了 ¬A |
| **新视角** | 多数人从角度 X 看，作者从角度 Y 看，且 Y 更解释力强 |
| **机制还原** | 多数人停留在现象，作者揭示了底层机制 |
| **边界界定** | 多数人混用 A / B，作者画清了 A ≠ B 的边界 |
| **反例 / 数据** | 多数人靠直觉，作者给了反例或硬数据 |

如果三段写完发现哪种都不算 → 这条不是亮点，删掉。

## 四、信心不足标注（差异化章节最容易触发）

调研做完后仍然没把握时，**才允许**用信心不足标注。格式严格：

```markdown
:::warn
**⚠️ 信心不足**
- 不确定点：……
- 已调研：检索词 / [来源](URL) / [来源](URL)
- 推测依据：基于 …… 做的判断
- 建议核对：建议读者去 ……
:::
```

HTML 渲染为 `<aside class="warn">`（参见 `html-style-spec.md`）。

### 使用约束
- **必须先调研，再标注**。没调研就标注 = 偷懒
- **必须留痕**。"已调研"那一行必须填检索词 + 至少 2 个来源
- **整篇 ≤3 处**。超过 3 处说明这篇内容根本不适合 distill，应该提示用户换内容
- **禁止整段落标注**。只标注到具体的句子或论断

## 五、反模式

- ❌ 跳过调研直接写差异化（这条最常犯）
- ❌ 把"作者文笔好" / "作者很认真"当差异化
- ❌ "多数人会说" 一栏写得太空泛 / 像在凑数
- ❌ "为什么有价值" 写成赞美而不是机制分析
- ❌ 用"信心不足"挡箭牌而不调研
