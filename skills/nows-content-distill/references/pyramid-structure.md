# Pyramid Structure · 核心概念 + 行文逻辑

本文档约束 `## 核心概念` 和 `## 行文逻辑` 两个章节的写作规范。

## 一、核心概念（术语层）

### 数量
- **3–7 个**。少于 3 个说明你没认真读，多于 7 个说明你在抄目录。

### 选择标准（满足任一即入选）
1. 这篇文章里反复出现，不懂就读不下去
2. 作者新造的词 / 重新定义的词
3. 作者引用的领域术语，但读者大概率没接触过

不入选：
- 全民共识词（如"互联网"、"AI"）
- 一次性出现且不影响理解的边角术语
- **金句 / 文化口号 / 单条建议**（如 "Make new mistakes"、"Don't sacrifice motion"）→ 这些是金句，归"值得记住的话"章节，不是核心概念
- **同一概念的两个变体拆成两张卡**（如"高能动性" + "高能动性 + 高问责"）→ 必须合并为一张

### 反凑数检查（写完核心概念后必做）

逐条问自己：
1. "把这个词从全文里去掉，理解会崩吗？" → 不会崩 = 它不是核心概念，删
2. "这个词跟列表里另一个词，是不是同一回事的不同说法？" → 是 = 合并
3. "这个词其实是一句金句的浓缩，还是一个真实的术语 / 概念？" → 金句的浓缩 = 移到金句章节

### 每条强制结构

```markdown
### {{术语}}
- 一句话：……
- 类比：……（可选）
```

**约束**：
- 一句话解释 ≤30 字，**禁止用行话解释行话**——如果解释里出现 B 概念，B 必须是大众已懂的
- 类比是可选项，但用了就要用读者熟悉的事物（"Asset 之于数据工程，就像 Makefile 的 target"）
- 区分**作者新造的词**（标 [新]）和**作者引用的既有术语**（不标）

### 反模式
- ❌ 抄词典定义
- ❌ 把"主语 + 是 + 名词"的循环定义当解释（"Agent 是一个智能体" → 啥也没说）
- ❌ 把背景知识塞进术语解释里

## 二、行文逻辑（金字塔）

这一节要做的是**反向工程出作者的思路**——不是复述顺序，是抽出骨架。

### 强制三层结构

```
顶层：作者的核心主张（≤30 字，必须可证伪）
  ├─ 论点 A —— 论据 a1, a2, a3
  ├─ 论点 B —— 论据 b1, b2
  └─ 论点 C —— 论据 c1, c2
```

### 三层各自的判定

**顶层主张**：
- ≤30 字
- **必须可证伪**——如果反过来说也成立，就不是主张。"AI 很重要"❌ / "通用 Agent 三年内做不出来" ✅
- 必须是**作者下的判断**，不是"这篇讨论了 AI 的发展"这种描述句
- **必须是作者原话或贴近原话的翻译**——优先抄原文里反复出现的那句金句作为顶层。如果作者反复说 "X is no longer the bottleneck, the new bottleneck is Y"，那**这就是**顶层主张，不要替作者重新概括成"X 时代的终极问题"

**禁止的顶层主张写法**：
- ❌ "X 时代的终极问题"（这是话题，不是判断）
- ❌ "本篇讨论了 X 的兴衰"（这是描述，不是主张）
- ❌ "X 正在改变 Y"（不可证伪——任何东西都在改变什么）
- ❌ 把多个观点缝合成的复合句（应该取最核心那一个判断）

**顶层主张的命中检验**：把它单独拎出来，能在原文里 ctrl-F 命中相近表达 → 合格；找不到任何对应原文 → 大概率是你自己的概括，不合格。

**论点（2–5 个）**：
- 论点是**作者用来支撑主张的子判断**，不是"段落小标题"
- 多了说明你没抽出主干，少了说明你没读懂
- 论点之间应该是**并列且互斥**的（MECE），不要有套娃
- **每个论点也应该贴近原文表达**——可以用自己的话整理，但不要替作者编一个原文没说过的观点

**论据**：
- 论据是**作者用来支撑论点的事实 / 数据 / 案例 / 引用**
- 论点和论据**必须分开**——这是骨架还原 vs 普通摘要的分水岭
- 论据要标明类型（数据 / 案例 / 引用 / 类比），帮助记忆

### ASCII 金字塔图（必须画）

放在章节最顶部，等宽字体，用 Unicode 盒形字符（`─│┌┐└┘`）。3 个论点的标准模板：

```text
                    ┌──────────────────────────────┐
                    │      {{顶层主张，≤30 字}}      │
                    └───────────────┬──────────────┘
                                    │
            ┌───────────────────────┼──────────────────────┐
            ▼                       ▼                      ▼
    ┌──────────────┐        ┌──────────────┐       ┌──────────────┐
    │ 论点 A        │        │ 论点 B        │       │ 论点 C        │
    └──────┬───────┘        └──────┬───────┘       └──────┬───────┘
           │                       │                      │
           ▼                       ▼                      ▼
        论据 a1/a2/a3           论据 b1/b2              论据 c1/c2
```

2 个论点 / 4 个论点的版本自行收缩或扩展，**不要用 Mermaid**（项目偏好 ASCII，HTML 用 `<pre>` 渲染等宽）。

### 反模式
- ❌ 把"小标题列表"当行文逻辑（那是目录不是逻辑）
- ❌ 论点和论据混在一起写（必须分层）
- ❌ 顶层主张写成不可证伪的口号
- ❌ 5 个以上论点（说明你没抽出主干）
- ❌ 没有 ASCII 图（金字塔不画出来读者就脑补不到结构）

## 三、与"差异化亮点"的边界

行文逻辑回答的是 "**作者怎么论证的**"，差异化亮点回答的是 "**这一篇相对于同类有什么独特贡献**"。
两者**视角完全不同**：前者向内看结构，后者向外看坐标。不要写串。
