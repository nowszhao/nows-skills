# Quality Checklist · 交付前自检

每次交付前必跑一遍。任一 ❌ → 回到对应步骤补，禁止跳过。

## 一、输入与抓取

- [ ] 输入类型已确认（粘贴正文 / 文章 URL / YouTube URL）
- [ ] 抓取后已让用户看过前 200 字并确认
- [ ] 抓取失败时已停下来要求用户补内容（**未用模型先验硬上**）
- [ ] 字数 / 时长在合理区间（文章 ≥300 字，视频转录 ≥500 字）

## 二、Markdown 结构

- [ ] frontmatter 6 个字段全填：`title / source_type / source_url / fetched_at / one_liner / word_count`
- [ ] 5 个 H2 章节顺序正确：核心概念 → 行文逻辑 → 差异化亮点 → 值得记住的话 → 最简复述
- [ ] 末尾有 `## 调研记录` 段落（HTML 不渲染但 MD 必须有）

## 三、核心概念

- [ ] 数量 3–7 个
- [ ] 每条都有 "一句话" 解释，且没用行话解释行话
- [ ] 解释 ≤30 字
- [ ] 区分了 [新] 造词与既有术语

## 四、行文逻辑

- [ ] 顶部有 ASCII 金字塔图（不是 Mermaid，不是文字描述）
- [ ] 顶层主张 ≤30 字且**可证伪**
- [ ] 论点 2–5 个，且**互斥并列**
- [ ] 论据和论点**分开**写（论点是判断，论据是事实）
- [ ] ASCII 图方框宽度统一、连线对齐

## 五、差异化亮点

- [ ] **强制调研已完成**且有留痕（`## 调研记录` 段落非空）
- [ ] 调研覆盖 3+ 来源、中英文检索词各做了一轮
- [ ] 1–3 条亮点，每条三段式齐全
- [ ] 每条亮点能落到 5 种价值类型之一（反共识 / 新视角 / 机制还原 / 边界界定 / 反例数据）

## 六、值得记住的话

- [ ] 数量 3–7 句
- [ ] 全部**逐字摘录**，无改写无意译
- [ ] 区分了观点型 / 事实型，事实型配了出处
- [ ] "为什么值得记" 命中误区/机制/反直觉/可迁移模板之一
- [ ] 视频金句配了时间戳

## 七、最简复述

- [ ] 字数 ≤500 字（已做 word count 核对）
- [ ] 连贯散文，无任何项目符号 / 列表 / 小标题
- [ ] 含四要素：问题 / 主张 / 证据 / 结论
- [ ] 饭桌口吻（不是论文腔，不是公众号腔）
- [ ] 自检反问 4 题全能答出

## 八、信心不足标注

- [ ] 标注前已做调研（不是裸标）
- [ ] 标注内 4 行齐全：不确定点 / 已调研 / 推测依据 / 建议核对
- [ ] 全篇 ≤3 处（超过则换内容）

## 九、HTML 渲染

- [ ] 单文件，所有 CSS 内联，无任何外部依赖（CDN / 字体 / JS / 图片）
- [ ] CSS 变量命名严格遵守 `--paper / --ink / --muted / --accent / --rule / --card / --warn-bg / --warn-line`
- [ ] 5 个 section 视觉处理与 `html-style-spec.md` 对齐
- [ ] 深色模式通过 `prefers-color-scheme` 自动切换
- [ ] 移动端 ≤640px 时差异化亮点的左右对照堆叠为单列
- [ ] 打印样式生效（`@media print`）
- [ ] 信心不足标注就近渲染，不集中在底部

## 十、产物交付

- [ ] `<slug>-distill.md` 与 `<slug>-distill.html` 同时输出
- [ ] 用 `preview_url` 打开 HTML 给用户预览
- [ ] Footer 的自检摘要数据真实（5 项是否齐 / 信心不足数 / 复述字数）
