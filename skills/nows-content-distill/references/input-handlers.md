# Input Handlers · 三种输入的处理细则

## 1. 文章正文（粘贴）

最干净的输入。直接进入 Step 2，不需要抓取。

**校验**：
- 字数 < 300 字 → 停下，提示用户"内容太短，distill 没意义，建议直接读原文"
- 全是导航菜单 / 广告 / 推荐位文案 → 停下，提示用户"看起来不是正文，请确认粘贴的是文章主体"

## 2. 文章链接（URL）

调用 `scripts/fetch_article.py`：

**抓取链路**：
1. 首选：WebFetch（Codebuddy 内置）
2. 兜底 1：`r.jina.ai/<URL>` 前缀走 Jina Reader 提取正文
3. 兜底 2：`curl` + 简单 HTML 清洗

**抓取后必做**：
- 把抓回来的**正文前 200 字 + 字数统计**打印给用户，让用户回 "ok / 不是正文 / 抓错了"
- 用户确认 ok 后才进入 Step 2

**抓取失败的处理**：
- 三层都失败 → **停下来**，提示用户"抓不到正文，可能是 paywall / 反爬 / 动态加载，请直接粘贴正文"
- 抓回来明显不是正文（菜单、cookie 提示、404 页面） → **停下来**，同上
- **禁止**：用 URL 自己猜内容硬上

## 3. YouTube 视频链接

调用 `scripts/fetch_youtube.py`：

**抓取链路**：
1. 首选：`youtube-transcript-api`，依次尝试语言 `zh-Hans` → `zh-Hant` → `zh` → `en` → `auto`
2. 兜底：`yt-dlp --write-auto-sub --skip-download --sub-lang ...` 拉 `.vtt` 后清洗
3. 都失败 → **停下来**，提示用户"该视频无可用字幕，请手工提供转录文本"

**抓取后必做**：
- 打印 `视频标题 / 作者 / 时长 / 字幕语言 / 字幕前 200 字`，让用户确认抓的是目标视频
- 时长 > 60 分钟 → 主动询问用户："全片处理还是分段处理？分段建议每段不超过 30 分钟"
- 时长 < 1 分钟 / 转录字数 < 500 字 → 停下来，"内容过短，distill 没意义"

**输出格式**（脚本统一返回）：
```
metadata:
  title: ...
  author: ...
  duration: 12:34
  url: https://www.youtube.com/watch?v=...
  language: zh-Hans
transcript: |
  [00:00] 首句
  [00:12] 第二句
  ...
```

**禁止**：
- 抓不到字幕时用 LLM 猜视频内容
- 抓错视频（标题对不上 URL）时硬上
- 仅凭视频标题写 distill

## 4. 不支持的输入（统一停止话术）

- B 站 / 抖音 / 小红书 / 播客 → "MVP 仅支持 YouTube。请先手工把转录文本粘贴进来。"
- 图片 / PDF / 截图 → "请先转成纯文本（OCR 或导出）再喂进来。"
- 多个 URL 一起丢 → "本 skill 一次只处理一条。请先指定第一篇。"

## 5. 抓取失败的硬约束（再强调一次）

输入污染 = 认知污染。**抓取失败必须停，禁止用模型先验硬上、禁止"全篇标注信心不足"挡箭牌。**
