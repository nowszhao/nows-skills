# 长文章、播客、演讲和视频的稳健处理

## 一、先判断读取能力，不假设已获取全文

1. **直接全文或文件**：读取完整章节，记录标题/页/段/行。有嵌入的图表、屏幕内容时，只有实际观察到才纳入证据。
2. **网页链接**：尝试读取正文，检查分页、付费墙、登录限制、折叠区域、附录。只拿到导语时记录`仅导语`。
3. **视频/播客链接**：优先带时间戳的官方字幕、转写或用户提供逐字稿；如果宿主有可用媒体读取能力，再补全画面/音频证据。不假定网站视频地址能直接转写。
4. **自动字幕**：说话人、时间戳和专名可能错；对数字、否定词、技术缩写、引用出处、关键主张保留不确定状态。若无法确认，不据此断言。

## 二、分片策略

- 依章节/话题转折优先切分，而不是固定字符断句；没有章节时可按约 **2,000–5,000 汉字**或**约 8–15 分钟字幕**一片（仅作工作建议，根据上下文容量调整）。相邻片段少量重叠，避免问答跨界被截断。
- 每片内部存 `片段 ID`、`原始时间/位置`、`本片候选 FAQ`、`主张 ID`、`来源锚点`、`疑点/未回答`。可以写在临时文件中，若宿主不支持文件系统则维护结构化中间摘要。
- 如果模型处理一片时无法保留所有来源信息，先做原文索引再总结；不能只保留机器生成的摘要，因为这样会丢证据。
- 对跨片论证（先提出问题、后面才回答），保留`待补全`状态，不在前一片就断定“没有回答”。

## 三、两遍扫描

**第一遍：完整覆盖扫描**

- 逐章节/时间段找到所有实质性问句和隐含问题，抽出作者答案和证据位置，保留未回答项。
- 标记转折词：`但是 / 然而 / 因此 / 首先 / 对此的反例 / 我认为 / 根据实验 / 举个例子`及原语中对应的表达；转折词提示重点但本身不是证据。

**第二遍：全局收敛**

- 合并同义问题，不能合并互相矛盾的回答。
- 把分散出现的同一问题的证据汇集到同一 FAQ，并保留**多个原文锚点**。
- 建立一级与二级层级，检验父问题是否被子问题共同回答。
- 识别跨片的前提、反驳、因果、对比与条件关系。
- 用覆盖索引逐段回查是否有遗漏的重要论点；给每片一个去向：`FAQ ID / 背景/寒暄/纯重复 / 无法确认`。

## 四、来源覆盖报告

按材料实际情况报告：

- `完整`：取得正文/字幕全量，全部主要篇章被扫描；**不代表没有任何识别误差**。
- `主要部分可读`：部分图片、付费段、缺失字幕、章节不可得。
- `节选`：用户只提供部分文本。
- `仅摘要/元信息`：不具备全文分析条件；不能列出“全部问题”。

不要编造精确覆盖率。只有原时长、字幕跨度或明确页数均已获知且可实际计算时，才可以写数字；同时指出不连续区段。

## 五、跨语言材料

- 结果使用用户语言（默认简体中文），技术名词第一次出现写原词；术语译法不确定时提供原文对照。
- 对关键词（如 `not`、`unless`、`may`、`could`）的否定、条件、推测语气忠实保留。
- 多讲者用 `讲者 A / 主持人 / 受访者` 分开归属；讲者身份不清时标`说话人未核实`。
- 演示类视频里的图表如无法看到，写“证据可能位于画面，当前未核查”，而非假设存在某组数据。

## 六、出错时的降级处理

- **全文无法取得**：给出已证实可访问范围和基于此的有限分析；清晰列出无法覆盖的部分。必要时请用户提供逐字稿/字幕。
- **来源超出处理能力**：按片分析、维护覆盖索引，交付完整目录和已验证的重点证据卡；不要冒称全覆盖。
- **外部检索不可用**：仍可做原文的 FAQ 金字塔与内部证据评价，但所有共识/原创性判断标待核验。
- **只有题目没有正文**：不能生成对内容的完整分析，可只告诉用户需要哪种输入。

## 七、交付前第三遍：逆向压缩完整性核验（强制）

前两遍用于构建内容；第三遍在**HTML 成品已经生成**后进行。按 `reverse-source-audit.md` 的独立来源台账逐段核对：

- `原文 → HTML`：每个核心/重要主张、关键论证、操作步骤、例子、反例和适用边界实际在哪里呈现？只是出现同一个名词不算覆盖。
- `HTML → 原文`：哪些结论、数字、因果解释和“行业共识”没有足够来源？有没有把作者的保留意见压缩掉？
- **迭代**：记录具体遗漏 → 修改 JSON → 再生成完整 HTML → 再审查；每次变更必须重新审核，不得复用旧版通过记录。
- **退出条件**：核心/重大要点无未解决的漏项或歪曲，主要结论可反查、界面展示无隐藏，审查范围可明确。不能访问完整材料则只做有限核对。
