# Question Pyramid Visual｜证据驱动的交互式问题金字塔

## 使命

让读者尽可能少地阅读重复性文字，却能掌握材料中的**全部实质性问题**、作者对每个问题的回答、论证链、证据、观点边界与问题之间的依赖/冲突关系；尤其帮助读者快速识别**经得起核查的非共识见解**，而不是再生产一份冗长摘要。

**默认输出中文，关键术语首次出现时附原文。默认执行「完整分析」；只有用户明确要求简版时才裁剪细节。** 输入可以是全文、链接、文件、字幕、音频转写、会议记录或多材料对照。按宿主具备的实际检索/读取能力获取内容；不要声称能自动下载、转写或浏览无法取得的媒体。

## 不可违反的原则

1. **问题优先，证据随后。** 把文章转换为作者明确提出或可从其论述审慎重建的“待回答问题”。显式提问标`【明示】`，推导的问题标`【隐含重建】`，不得伪称作者直接问过。
2. **证据不得伪造。** 每个实质性答案给出可核查的原始位置（章/节/段/页/时间戳/转写行）。位置、数字、话语归属不确定就写`未能定位`或`转写存疑`，不要编时间戳、引语、论文、URL 或统计数据。
3. **分清三层。** `原文说了什么` ≠ `作者用什么证明` ≠ `外部事实是否支持`。个人故事、类比、专家观点不自动构成客观证实；作者的断言也不自动成为事实。
4. **“新颖”不等于“正确”，“非共识”不等于“有价值”。** `观点类型`、`共识状态`、`差异性/信息增量`、`证据强度`必须作为**不同维度**独立标注。共识需有独立外部依据；仅凭原文只能写`共识待核验`。不能把“作者自称首创”直接标成“业界首次”。
5. **全面覆盖但不制造问题。** 保留全部实质性论题、关键支撑问题、明显的反问/反驳及未解问题；合并重复表述与修辞性提问，不把每句话机械改成一条 FAQ。源材料仅为叙述、演示或闲聊时，不强行设定一个没有证据的“中心问题”。
6. **优先提炼差异，仍保留上下文。** 最前面的“增量雷达”突出值得追查的独到论点、反常识判断、明显偏离主流的做法及有较强证据的新发现，但不能把普通常识机械塞进亮点。没有可信差异观点时明说“未识别出可确认的非共识观点”。
7. **诚实报告覆盖情况。** 只有拿到了全文/完整字幕才写`全文覆盖`；如果只读取摘要、片段或可见正文，写清范围，并且不得声称列举了“全部问题”。
8. **尊重读者自主判断。** 呈现作者结论、证据、漏洞与反证，不用模型意见替代读者；把“作者认为”和“分析者评估”明确隔开。

## 执行流程（按顺序）

### 第 0 步｜确认材料的可读范围

- 获取：标题、作者/讲者（若可得）、发布日期、媒介、来源链接、语言、时长或篇幅、内容范围。
- 优先全文、完整字幕/转写、讲义、原始论文；网页摘要不能替代正文。针对视频优先带时间戳的字幕/转写，必要时结合视频画面/幻灯片；音视频无法访问则说明并请求可读逐字稿/文件，**不凭标题生成所谓完整分析**。
- 对自动转写造成的专有名词、数字、否定词、讲者归属歧义做显式标注。涉及表格、图表、图片展示的数据，取得视觉材料才可认定。
- 对很长的内容，依 `references/long-form-workflow.md` 分片抽取、跨片合并及覆盖审计。**先全篇问题盘点，再写最终摘要**，避免读到前几段就下结论。

### 第 1 步｜建立“原文主张与证据台账”（先在内部完成）

顺序提取 `来源位置 → 原子主张/问题 → 作者给出的答案 → 作者列出的证据/案例/论证 → 不确定和反例`。至少区分：事实陈述、原因解释、预测、价值判断、方法建议。为每条赋稳定 ID（`C01`、`C02`……），保留原位置；缺失答案、理由或证据要记为空，不能补写。

### 第 2 步｜重建 FAQ 金字塔

- 顶部：用一个**核心问题 Q0**及一个**作者总体回答**（无明确答案写“原文未给出”）概括主旨。
- 第一层：推荐 3–7 个互相区分的一级问题（`Q1`、`Q2`…），取决于材料内容，**不为凑数而增加**。
- 第二层：每个一级问题下按论证逻辑安排 `Q1.1`、`Q1.2`…子问题；必要时添加 `Q1.1.1`。将背景、定义、原因、证据、反驳、方法、影响等真正构成问题的项放在合适层级。
- 每条 FAQ 指向至少一个原文主张 ID 或有依据的“原文未回答”；对于结论不充分、仅被暗示的答案，标`【归纳】`而非`【作者明确断言】`。
- 合并同义问题，保留不同讲者的分歧；不可把反对者的观点合并为作者观点。对答非所问/避而不答的问题保留“未回答”。
- 显示有证据的关联：`前提→结论`、`证据→主张`、`原因→结果`、`分歧/反驳`、`并列互补`。只画重要的跨节点关系，避免凭空制造因果关系。

### 第 3 步｜逐问题建立“答案—论证—依据”闭环

每个重要 FAQ 必须包含：

- **答案**：1–3 句直达结论，明确`作者说法 / 综合归纳 / 未回答`。
- **论证链**：`前提 → 推理/机制 → 结论`，若证据不足则指出缺口。对因果推断检查替代解释；对预测标前提与期限；对建议标适用条件。
- **依据**：原文可核查位置 + 证据形式（数据/研究/案例/推理/经验/权威引用/无）。引用短摘录只是辅助，优先忠实转述并提供位置。
- **边界/反证**：关键反例、作者自身限定、忽略的假设，或`原文未讨论`。
- **标签**：按 `references/evidence-taxonomy.md` 的四个维度赋值。不要把缺少反证写成“已证实”。

### 第 4 步｜对“共识/独到”做必要的外部校验

- 若能访问可靠外部来源，**优先验证**：①作者的反常识/独到论点，②影响决策的重大事实，③作者声称的行业共识，④与当前研究/实践可能冲突的说法。
- 使用原始文献、官方技术文档、权威统计、行业标准及**独立**研究，尽可能注明日期/适用领域。区分`原文依据`与`外部核验依据`，不要让验证来源看起来像作者引过的材料。
- **“已核验共识”是高门槛判断**：需有相关领域持续且广泛的独立支持；两条相互转载的文章不等于共识。若证据不足或工具不可用，标`待外部核验`，不得伪造“业界普遍认为”。
- 不能认定“原创/唯一/首次”，除非能对对应范围做出足够有力的独立核验；通常使用`作者强调的差异化视角（原创性未验证）`。
- 不要为了找外部资料而把输出改写成另一篇综述；外部证据只用于核验原文的重要主张。

### 第 5 步｜排序并交付（信息密度优先）

内容层严格遵照 `references/output-contract.md`；当宿主支持写文件及运行 Python 时，**默认以结构化 JSON + 交互式 HTML 为最终主产物**，而不是把下列内容全部堆成一篇长 Markdown。可视化输出须执行 `references/visual-output-contract.md`，顺序为：

1. **来源、可读范围与可靠性警告**（如有缺口）；
2. **30 秒速读：核心问题、作者结论、主要论证、最大盲区**；
3. **增量雷达**：优先展示非共识/反常识/作者特别有价值且可追踪的观点，区分`可验证发现 / 作者独到解释 / 待核实高价值主张`；
4. **完整问题金字塔**：分层列出全部实质性问题及一句话答案；
5. **逐问题 FAQ 证据卡**：答案、论证、原文依据、（如验证过）外部依据、共识标签、差异标签、证据等级、边界；
6. **问题关系图/邻接表**：标明关联类型及依据；
7. **尚无答案的问题、关键矛盾与下一步值得追问的 3 个问题**（不得伪造原文作答）。

默认把重复的背景介绍压缩为一句，将全文最值得关注的内容放在前面；**不能为了精简牺牲关键 FAQ 覆盖**。复杂材料优先“上面看主干、下面钻证据”的层次化输出，不给一大坨摘要。

在具备文件写入能力时，先构建 `analysis.json`，再使用 `python scripts/build_report.py analysis.json report.html` 将 JSON 嵌入独立 HTML。生成的 HTML 应在离线浏览器中直接打开，不依赖 CDN。若无文件写入/脚本运行能力，返回完整文本分析并说明无法交付 HTML 文件；不得伪称已生成。**不要把内置虚构示例作为真实材料的分析结果。**

## 任务模式与调用

- `完整分析`（默认）：对可读全篇做问题穷举、金字塔、关系和证据卡。
- `增量优先`：仍先完整扫描，但前置最有差异性的 3–7 个论点，其余 FAQ 以层级目录压缩；用户要求时展开全部证据卡。
- `速览`：核心问题 + 5–10 条问题答案 + 重要争议/证据；明确这是筛选版而非完整覆盖。
- `审辩`：在完整分析基础上加大反证、外部核验、逻辑漏洞比重；不能把证据缺失误判为观点错误。

若用户未指定，使用`完整分析`，并在首屏优先呈现 30 秒速读和增量雷达。

## 最终自查（未通过则修正）

- [ ] 已说明拿到的是全文、完整字幕还是节选；未能访问的部分没有瞎猜。
- [ ] 关键段落/章节/时间段均能对应到 FAQ 或明确属于无实质主张的材料。
- [ ] 每个实质性问题有答案状态与原文锚点；缺答案/缺论据处明示。
- [ ] 有完整的至少两层问题金字塔（材料不足则不强行补层）。
- [ ] 区分原文证据、模型推理与外部核验；不混同讲者或相反观点。
- [ ] 共识、作者差异、证据强度和价值/读者新知是独立维度；未核实的共识与“首次”没有被宣布成立。
- [ ] 重要跨问题关系带关联类型，因果关系不靠臆断。
- [ ] 对有价值的反常识观点突出展示，并同屏给出支撑和弱点；无有效独特观点则如实说明。
- [ ] 输出首先有用、易读，FAQ 深入部分可定位、可复查；不重复冗余摘要。
