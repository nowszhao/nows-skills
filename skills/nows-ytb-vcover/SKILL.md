# Nows Ytb Vcover

## Overview

把 YouTube 链接一次性转化为两份可交付物，**按视频 ID 建文件夹存放**：
1. **发布文案 Markdown**（长标题 + 缩略图小标题 + 简介：原视频地址 / 发布时间 / 内容提炼 / 标签），各部分独立成块、**支持一键复制**，用于公众号、小红书、知乎、B 站等二次分发；
2. **视频封面 HTML**（**1280×960，4:3 比例，适配首页渲染**；B 站风格，深色渐变 + 数学网格 + 橙色高亮）。封面主标题采用**"观众关心的问题"句式**制造悬念吸引点击，副标题一句话交代内容定位。

单集与批量模式统一产出结构：`<视频ID>/文案.md + <视频ID>/封面.html`。

## 工作流决策树

- 输入为单个 `watch?v=` URL（可带 `&t=` 时间参数）→ **单集模式**（步骤 1-4）
- 输入带 `&list=` 参数或用户明确要求系列/播放列表 → **批量模式**（步骤 1-5）

## Step 1：抓取元数据

运行抓取脚本（封装 yt-dlp，自动加 chrome cookies 规避 bot 验证）：

```bash
python3 ~/.workbuddy/skills/nows-ytb-vcover/scripts/fetch_metadata.py "URL"
```

脚本行为：
- 单集 URL：抓取该视频，输出 JSON 到 stdout；
- 播放列表 URL（`&list=` 参数）：抓取列表内全部视频，输出 JSON 数组，每条记录间以 `###SPLIT###` 分隔，首条前打印 `PLAYLIST_META|频道|数量` 行；
- 失败提示：若报 bot 验证错误，确认本机 Chrome 有 YouTube 登录态后重试，必要时改用 `--cookies-from-browser safari`。

## Step 2：提取关键字段

每个视频提取：`id`、`title`、`upload_date`（YYYYMMDD，展示转 YYYY-MM-DD）、`duration`（秒，转 h:mm:ss）、`view_count`（转万/K 格式）、`channel`、`description`、`tags`、`chapters`。

## Step 3：创建输出文件夹

按视频 ID 创建输出目录（产出物统一放这里）：

```bash
mkdir -p "<输出根目录>/<视频ID>"
```

- 单集：`<视频ID>/` 下一个视频一套文件；
- 批量：每集一个 `<视频ID>/` 子目录。批量场景如需额外系列总览，可在输出根目录放一个 `系列总览.md`。

## Step 4：生成发布文案 Markdown

严格遵循 `references/copy-template.md` 的模板与示例，产出 `<视频ID>/文案.md`：
- **长标题**：信息量 + 钩子，突出核心价值，中文，30-60 字；
- **缩略图小标题**：6-12 字，大字、有冲击力；
- **封面标题**：给 **2-3 套方案**（每套 = 主标题 + 副标题），供用户按需选择最终视频标题；封面.html 默认采用方案一；
- **简介**：原视频地址（`https://www.youtube.com/watch?v=<id>`，去掉 `&list`/`&t` 参数）+ 发布时间 + 时长/播放量 + 内容提炼（结合 description 与 chapters 改写为中文干货要点，不照抄英文）+ 标签（中英混排，`#SemanticLayer` 风格）；
- **可复制性要求**：长标题、缩略图小标题、封面标题、简介各自用 fenced code block（` ```text `）包裹**纯文本**，使读者可一键复制到社媒编辑器，无 markdown 符号残留（详见 copy-template.md）。

## Step 5：生成封面 HTML

用 `assets/cover-template.html` 作为基底，按以下规则填充（改文案，保留结构与样式体系），产出 `<视频ID>/封面.html`：
- **主标题（h1）**：默认采用文案.md 中**封面标题方案一的主标题**——用**观众关心的问题句式**陈述，从视频里提炼"目标观众最想知道答案的问题"，制造悬念。2 行以内大字，可用 `<span class="hl">` 高亮关键词，字号 90-120px（长标题可降至 64px）；
- **副标题（sub）**：对应方案一的副标题——一句话内容定位，交代视频讲什么；
- **kicker**（主标题上方小字）：最强卖点或场景引导；
- **badge**（左上）：`<频道/嘉宾> × <来源>` 形式；
- **feature-tag（差异化优势标签，必须强化）**：主标题上方的绿色发光大标签「真人感中文配音」（34px 大字 + 麦克风图标，置于 kicker 之前），这是区别于其他视频的差异化优势，**每个封面必须保留并保持醒目，不得删除、缩小或改动文案**；
- **footer**：来源说明 + 时长（右上角 `live-tag` 可用"首发/实录/对谈"等场景词替换）。
- **纵向布局必须紧凑**：4:3 画布采用整体居中的三段式内容组（`topbar → main → footer`），禁止使用 `space-between` 或 `main: flex: 1` 撑开上下空隙；`.cover` 固定使用 `justify-content: center; gap: 36px;`，`.main` 固定使用 `flex: none; display: block;`；外层间距约 36px，主视觉标签与 kicker 间距约 18px，kicker 与主标题间距约 12px，主标题与副标题间距约 20px。以截图观感为准，保证主体内容聚拢在画布中部，顶部信息条和底部信息条之间不出现大块空白。
- 封面文件名固定为 `封面.html`（位于 `<视频ID>/` 内）。
- **若用户选定封面标题的其他方案**：按所选方案更新主标题/副标题并重新生成封面.html。

## Step 6：批量模式汇总

- 每集独立产出 `<视频ID>/文案.md` + `<视频ID>/封面.html`；
- 如需系列总览：输出根目录放 `系列总览.md`（名称、频道、定位、播放列表地址、逐集清单）；
- 全部产出后统一 `present_files` 展示（文案在前，封面随后）。

## Pitfalls

- 不要直接用 WebFetch 抓 YouTube 视频页：内容随机且受 bot 验证影响；统一走 fetch_metadata.py（yt-dlp + cookies）。
- upload_date 是 YYYYMMDD，展示必须转成 YYYY-MM-DD。
- 简介中"原视频地址"去掉 `&list` / `&t` 等追踪参数。
- 文案 Markdown 的可复制块必须用纯文本（无 `**` / `-` 等 markdown 符号），否则粘贴到社媒平台会有残留字符。
- 封面 HTML 是给截图用的：字号要足够大（普通主标题 90-110px，超长标题可降至 64px），对比要强；不要在封面里堆太多文字。
- 封面画布固定 **1280×960（4:3）**，适配首页渲染；不要改回 16:9 或其他比例。
- 若修改已有封面比例或布局，必须同步检查所有已生成的 `<视频ID>/封面.html`，避免模板与历史产出不一致。
- 封面主标题优先用"观众关心的问题"句式，而非平铺直叙的陈述句；避免用视频原英文标题直译。
- 输出文件夹名必须是视频 ID（如 `yAvJ7b_FxUA`），不要用中文名或标题代替。
