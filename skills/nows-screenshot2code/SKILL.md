# nows-screenshot2code — 截图转前端代码

把截图、设计稿、UI 图片转换为像素级还原的前端代码。最终产出一个**单文件、自包含、可直接预览的 HTML**（所有 CSS/JS 内联，依赖走 CDN）。

## 核心交付标准

一份合格的产物必须让用户在浏览器里打开后，与原截图**肉眼看不出明显差异**：布局结构、颜色、字体、间距、连接线、装饰元素全部对齐。

如果用户打开后能一眼指出"这个少了""这个位置错了""这个颜色不对"，产物就是不合格的。

---

## 前置准备

### 输入确认

拿到截图后，先确认以下信息。如果用户给得足够明确（直接丢图说"还原成 HTML"），不要追问，直接开始：

1. **截图来源**：网页截图 / 设计稿（Figma、Sketch 导出）/ App 截图 / 手绘草图？
2. **技术栈偏好**（可选）：用户指定用哪个 stack？默认 `html_tailwind`（大多数设计最快、默认值好）。
3. **是否多图**：多张截图是同一页面的不同状态、不同页面、还是无关图？

### 环境能力

本 skill 强依赖**视觉对比能力**来完成自检：

- **首选**：环境中如果有浏览器自动化工具（如 `agent-browser`、`browse`、headless chromium），用它截图并和原图做并排对比
- **降级**：没有浏览器自动化时，用 `preview_url` 打开生成的 HTML，依靠模型自身的图像理解能力逐项对比
- **辅助**：颜色提取用 `scripts/color_extractor.py`（需要 `pip install Pillow scipy numpy`），结构校验用 `scripts/validate_output.py`

## 第一步：分析截图（写代码前必做）

这一步是 #1 错误来源。**不分析就开写 = 必返工**。

### 1. 布局结构（最容易翻车）

采用 **grid-first 分析法**：

- 在截图上心里画网格，先数行（横向条带），再数每行内的列
- **先把网格写下来再写代码**。示例：
  ```
  Row 1: [col-3] [col-6] [col-3]
  Row 2: [col-12，内部 3 列]
  Row 3: [col-12（5 张卡片）]
  ```
- **不要猜嵌套关系**：一张占满整宽的卡片是独立一行，不是上一列的子区块
- **如果用户说"X 应该在 Y 里面"或"X 和 Y 不在同一区块"**——重新审视**整个**布局层级，不是只改那一个元素。你的网格心智模型大概率整体错了
- **连接线 / 箭头 / 分隔线**：显式扫描截图找这些，极易漏看但对布局保真至关重要
- **匹配原审美**：原图用简单三角箭头（▶），就别加圆形边框或装饰包装。极简是刻意的，不要"升级"

### 2. 颜色

- 提取背景色、文字色、强调色、边框色
- 记录渐变和透明度
- **精确提取**用 `scripts/color_extractor.py`：
  ```bash
  python scripts/color_extractor.py screenshot.png --count 8
  ```

### 3. 字体

- 识别字体族、字号、字重
- 记录标题层级（h1-h6 字号）
- 观察行高和字间距

### 4. 间距与尺寸

- 记录 padding、margin、元素间距
- 识别元素宽度（满宽 / 居中容器 / 固定宽）
- 观察圆角值

### 5. 资源

- 识别图片、图标、logo
- 判断图标是 Font Awesome / 自定义 SVG / 图片
- logo 用描述性 alt 文本，便于后续替换

### 6. 交互元素

- 按钮、链接、表单、下拉、弹窗
- hover / active 态

## 第二步：选择技术栈

问用户偏好，或按设计复杂度推荐：

| Stack | 适用场景 |
|-------|---------|
| `html_tailwind` | 大多数设计，快速开发，默认值好（**默认选这个**） |
| `html_css` | 简单设计，不依赖框架 |
| `react_tailwind` | 复杂交互 UI，组件化 |
| `vue_tailwind` | Vue.js 项目 |
| `bootstrap` | 标准后台 / 仪表盘 |
| `ionic_tailwind` | 移动优先 / App 风格界面 |

各 stack 的 CDN 配置和注意事项见 `prompts/templates.py` 中的 `STACKS` 定义（已硬编码版本号，避免兼容问题）。

## 第三步：生成代码

产出**单一、自包含的 HTML 文件**。

**硬规则：**

- 一次性写完整文件——不要拆成多个文件
- 用文件创建工具写入 `index.html`
- 文件必须完全自包含：HTML + CSS + JS 全部内联
- 框架走 CDN（Tailwind、React、Vue、Bootstrap、Ionic）
- 不要引用本地文件路径
- 图片用占位 URL 或描述性 alt，标注哪些需要替换为真实资源

### 文字可编辑（硬性要求）

生成的页面里**所有可见文字**都必须支持点击即编辑。用户在任意文字上点击，该文字进入可编辑状态，可直接修改内容；点击别处或按 Esc 退出编辑。

实现规范：

- **通用方案**（适用于所有技术栈）：给承载文字的元素加 `contenteditable="true"`，包括 `<h1>`~`<h6>`、`<p>`、`<span>`、`<li>`、`<td>`、`<label>`、`<a>` 的文本、卡片标题 / 正文等
- **范围控制**：只给文本内容元素加 `contenteditable`，不要加到纯布局容器（做布局用的 `<div>`）、按钮图标、`<img>`、`<svg>` 上
- **React / Vue 栈**：不要用框架状态管理编辑逻辑，直接用原生 `contenteditable` 属性，保持单文件自包含、零额外状态复杂度
- **视觉反馈**：编辑态可加极淡背景色或虚线下划线提示"正在编辑"，但**非编辑态下不得有任何视觉提示**——页面静态外观必须和原图一致
- **Esc 退出**：监听 `keydown`，按 Esc 时 `blur()` 当前编辑元素
- **不破坏布局**：编辑时文字长度变化不能撑破布局，用 `min-width` 或 `white-space` 控制

参考实现（直接内联到生成的 HTML `<body>` 末尾）：

```html
<style>
  [contenteditable="true"] { outline: none; }
  [contenteditable="true"]:focus {
    background-color: rgba(59, 130, 246, 0.08);
    box-shadow: 0 0 0 2px rgba(59, 130, 246, 0.3);
    border-radius: 2px;
  }
</style>
<script>
  document.addEventListener('keydown', (e) => {
    if (e.key === 'Escape' && document.activeElement?.isContentEditable) {
      document.activeElement.blur();
    }
  });
</script>
```

## 第四步：自检验证（不要靠记忆）

**不要靠视觉记忆对比。** 每次迭代都用自动化对比：

1. **生成 HTML 后，渲染并截图**：
   - 有浏览器自动化工具时（首选）：
     ```
     打开 file:///path/to/index.html
     等待 networkidle
     全页截图到 /tmp/v1.png
     ```
   - 无浏览器自动化工具时：用 `preview_url` 打开，依赖模型的图像理解能力

2. **做并排对比图**（有 PIL 时）：
   ```python
   from PIL import Image
   orig = Image.open('/path/to/original.jpg')
   impl = Image.open('/tmp/v1.png')
   # 把两张图缩到同宽，左右拼接，分别标 "Original" / "Current"
   ```

3. **读对比图，列出所有差异**：
   - 布局结构（网格行列错误）
   - 漏掉的连接线 / 箭头
   - 颜色、间距、字体不对
   - 多出了原图没有的装饰

4. 用定向编辑修复差异，然后重新截图、重新对比。

5. **重复直到并排对比图看不出有意义差异。**

6. 结构改动后，验证交互功能（编辑态、点击处理）仍然正常。

这套「截图 + 并排对比 + 定向修复」循环，是达到像素级保真最可靠的方法。

## 自检清单

交付前逐项对照原截图检查：

| 类别 | 检查项 |
|------|--------|
| **布局** | □ 区块顺序一致 □ 列/行结构一致 □ 父子层级正确（X 没被错误嵌进 Y） |
| **连接线** | □ 列间箭头 □ 步骤间箭头 □ 流程线 / 分隔线 □ 虚线 |
| **颜色** | □ 背景色 □ 文字色 □ 强调 / 品牌色 □ 边框色 |
| **字体** | □ 字体族 □ 标题字号 □ 正文字号 □ 行高 |
| **间距** | □ 区块 padding □ 元素 margin □ 元素间距 |
| **内容** | □ 所有文字都在且正确 □ 图片 / logo 已标注 □ 没有原图没有的装饰 |
| **细节** | □ 圆角 □ 阴影 □ 按钮样式 □ 图标风格匹配原图（简洁 vs 装饰） |
| **交互** | □ 结构改动后编辑态仍可用 □ JS 处理器正常 |
| **可编辑** | □ 所有可见文字点击即可编辑 □ 非编辑态零视觉提示 □ 编辑不撑破布局 □ Esc 可退出 |
| **响应式** | □ 常见宽度下布局不崩 □ 文字可读 |

任一项不过，先修再交付。

## 常见坑（来自真实迭代）

这些是把复杂图转代码时最频繁、最贵的错误：

### 坑 1：布局层级猜错（最常见）

**症状**：用户说"X 应该在 Y 里面"或"布局不对"。

**根因**：靠猜嵌套关系而不是 grid-first 分析。占满整宽的卡片不是上一列的子区块——它是独立一行。

**修法**：写任何代码前，先画网格：
```
Row 1: [col-3] [col-6] [col-3]
Row 2: [col-12，内部子列]
Row 3: [col-12（5 张卡片）]
```
拿这个网格对照原图验证。用户纠正你时，说明网格错了——重画。

### 坑 2：漏掉连接线 / 箭头

**症状**：截图里组件之间有箭头，HTML 里没有。

**根因**：连接线是视觉"胶水"，聚焦内容块时极易忽略。

**修法**：第一步分析时显式扫描：
- 列间的横向箭头
- 步骤间的纵向箭头
- 虚线、雪佛龙、流程指示
- 用纯 CSS 实现（`::after` 伪元素、border 技巧、Flexbox gap），不要用绝对定位的 SVG 叠加——布局一变就维护地狱

### 坑 3：过度装饰

**症状**：HTML 看着"太 AI 味"——原图没有的边框、图标、渐变全冒出来了。

**根因**：默认"弄好看点"而不是"精确匹配"。

**修法**：原图用简单三角（▶），就别包圆框。原图卡片上没图标，就别加。匹配原图的审美级别——极简是刻意的。

### 坑 4：不用自动化对比

**症状**：靠肉眼迭代了 6 版还在 v6 才发现布局错。

**根因**：人眼视觉记忆对像素级对比不可靠。

**修法**：每次迭代都用浏览器截图 + PIL 并排对比（见第四步）。v2 就能抓住的错，别拖到 v6。

### 坑 5：结构改动搞坏交互

**症状**：移动了几个块之后，编辑态或其他 JS 功能失效。

**根因**：DOM 重构改变了 JS 查询依赖的元素路径。

**修法**：任何结构改动后，用浏览器快照和点击测试交互功能。

### 坑 6：用户反馈布局 → 只局部打补丁

**症状**：用户说"布局错了"，你只改了那个元素，没找到根因。

**修法**：用户给布局反馈时，**不要局部打补丁**。重新通读原图，重画网格，逐行逐列对照用户说法。问题往往是层级的（元素放错了父节点），而不是位置的（在正确父节点里位置不对）。

### 坑 7：文字可编辑搞坏布局 / 加了多余视觉提示

**症状**：开启 `contenteditable` 后，文字编辑时撑破容器，或非编辑态出现了下划线 / 边框 / 背景色等原图没有的视觉元素。

**根因**：浏览器默认给可编辑元素焦点轮廓，且编辑时内容长度变化影响布局宽度。

**修法**：
- 给 `[contenteditable]` 加 `outline: none`，只在 `:focus` 时用极淡背景色提示，非焦点态零视觉变化
- 用 `min-width` 或 `white-space: nowrap`（视场景）防止编辑撑破
- 结构改动后必须重新测试可编辑功能是否仍正常

## 边界情况与提示

- **低对比度文字**：确保文字满足 WCAG AA（对比度 ≥ 4.5:1）
- **重叠元素**：谨慎用 z-index，验证层级顺序
- **渐变**：精确复刻渐变停止点和方向
- **毛玻璃 / 模糊**：用 `backdrop-filter: blur()` 并配降级方案
- **未知字体**：描述特征，用最接近的 Google Font
- **占位图**：用描述性 alt 文本，标注哪些图需要真实资源
- **动画**：截图是静态的，看不出来动画——如果疑似有动画，向用户说明并标注

---

## 多截图处理

如果提供了多张截图：

- **不同页面** → 创建独立页面，加导航链接
- **不同 tab / 视图** → 做 tab 切换或视图切换
- **无关** → 分区标注"截图 1""截图 2"等
- **移动端截图** → 去掉设备框 / 浏览器 chrome，只还原 UI 内容

## 反模式（禁止）

- ❌ 不分析截图直接开写代码（必返工）
- ❌ 靠猜嵌套关系而不是 grid-first 分析
- ❌ 用户反馈布局问题时只做局部补丁，不重新审视整体网格
- ❌ 漏掉连接线 / 箭头 / 分隔线
- ❌ 给原图没有的元素加装饰（边框、图标、渐变、圆框包箭头）
- ❌ 靠视觉记忆对比，不用自动化截图对比
- ❌ 拆成多个文件输出（必须单文件自包含）
- ❌ 引用本地文件路径（必须走 CDN 或占位）
- ❌ 改了结构不测交互功能
- ❌ 用绝对定位 SVG 叠加做连接线（布局一变就崩）
- ❌ 编造截图里没有的文字内容（必须逐字复刻原图文字）
- ❌ 生成的文字不支持点击编辑（所有可见文字必须 `contenteditable`）
- ❌ 非编辑态给文字加视觉提示（下划线 / 边框 / 背景色），破坏像素保真
