# PRD 模板

> **边界**：PRD 只写 What & Why（业务规则 / 字段约束 / 状态机 / 权限 / 埋点）。
> 不写 How（API、DDL、技术选型、Feature Flag 命名、P99/QPS） —— 这些归 Tech Spec。
>
> §1 标准 PRD（2-5 个故事） · §2 One-Pager（1 个故事） · §3 写完自查
> 标 `（如适用）` 的节没内容直接删。

---

## §1 标准 PRD 模板

```markdown
# PRD：{特性名称}

| 作者 | 版本 / 日期 | 状态 | 所属 Epic |
|------|------------|------|----------|
| … | v0.1 / YYYY-MM-DD | Draft / Review / Approved | … |

## 1. 概述
一段话讲清：做什么、给谁、解决什么、成功长什么样。

## 2. 问题与目标
- **问题**：当前痛点（带数据或案例）
- **不做的代价**：…
- **目标**：要达成的结果（Outcome，不是 Output）
- **Non-Goals**：本期明确不做什么
- **成功指标**：

| 指标 | 口径 | 当前值 | 目标值 |
|------|------|--------|--------|
| … | … | … | … |

## 3. 用户与场景
- **目标用户 / 角色**：…
- **端到端场景**：串联各故事的闭环流程

## 4. 用户故事与验收标准

### US-1：{标题} `P0`
> 作为 {角色}，我想 {能力}，以便 {价值}

| AC | Given | When | Then | 关联需求 |
|----|-------|------|------|---------|
| AC-1 | 用户在 X 状态 | 执行 Y | 期望 Z | R-1 |

完成定义：全部 AC 通过 → US-1 完成 ✅

（US-2、US-3… 同结构）

## 5. 功能需求清单

| ID | 需求描述 | 服务故事 | 业务规则 / 约束 | 状态流转 | 异常处理 | 可见角色 | 优先级 |
|----|---------|---------|----------------|---------|---------|---------|--------|
| R-1 | … | US-1 | 同租户内名称唯一 | 草稿→提交→发布 | 重名→提示改名 | Owner、Admin | P0 |

## 6. 设计

### 6.1 入口与关键界面
- **入口**：导航位置 / 触发动作
- **关键界面**：原型链接 + 关键截图，每个界面覆盖 5 态：默认 / 加载中 / 空 / 错误 / 极端数据

### 6.2 表单字段规约（如适用，有表单必填）

**表单：{表单名}**

| 字段 | 业务含义 | 必填 | 默认值 | 校验规则 | 错误文案 | 校验时机 |
|------|---------|------|--------|---------|---------|---------|
| 名称 | 数据集名称 | ✅ | — | 长度 1-32、字母数字下划线、租户内唯一 | "名称已存在" | 失焦+提交 |
| 描述 | 用途说明 | ❌ | 空 | ≤ 200 字 | "最多 200 字" | 实时计数 |

- **字段间约束**：如「类型=STREAM」时，「保留期」由可选变必填
- **提交行为**：成功跳转 X + 提示；失败错误对应到字段下；不可重复提交

### 6.3 关键交互流程（如适用）
跨页 / 异步 / 长流程的状态图或步骤，含失败 / 中断 / 并发冲突的回滚路径。

## 7. 业务规则与全局约束（如适用，有核心对象必填）

- **状态机**：如 数据集：草稿 → 已发布 → 已归档 → 已删除，含触发条件
- **配额与限制**：数量上限、频率限制
- **可见性 / 数据范围**：个人 / 团队 / 租户 / 全局
- **审计要求**：哪些操作需留痕

## 8. 度量与埋点

| 事件 | 触发时机 | 关键属性 | 对应指标 |
|------|---------|---------|---------|
| feature_xxx_used | 用户完成 Y | user_role, source | 采纳率 |

## 9. 发布与兼容（如适用）
- **发布节奏**：Preview / 灰度 / GA 的时间与范围
- **兼容与迁移**：老用户 / 老数据 / 老链接 的过渡（业务层面）

## 10. 风险与开放问题

| 类型 | 内容 | 影响故事 | 缓解 / 待澄清 | 负责人 |
|------|------|---------|--------------|--------|
| 产品 / 法务 / 资源 | … | US-? | … | … |

## 11. 追溯与变更

- **追溯**：Epic → Feature → US → R → AC → 埋点
- **变更记录**：

| 版本 | 日期 | 变更点 | 影响故事 |
|------|------|--------|---------|
| v0.1 | … | 初稿 | — |
```

## §3 写完自查

- [ ] 全文未出现 API / DDL / 字段类型 / Feature Flag 名 / 中间件选型
- [ ] 每个 US 至少 1 个 R-ID；每个 R 至少服务 1 个 US；每个成功指标至少 1 个埋点
- [ ] 涉及的表单都填了字段规约；涉及的核心对象都写了状态机
- [ ] 每个 AC 满足"可独立测试"（Given/When/Then 可执行）
- [ ] 推断处都标了 `[待确认]`；不适用的「如适用」节已删除
