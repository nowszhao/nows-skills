# 概念层级依赖图生成器

根据用户的当前知识起点和目标概念，逆向拆解完整的前置概念依赖链条，生成包含 dagre 分层拓扑图和概念速查表的交互式 HTML 报告。

## 触发场景

- 用户想了解掌握某个复杂概念需要哪些前置知识
- 用户需要从当前水平到目标概念的结构化学习路径
- 用户想看清一组概念之间的层级依赖关系
- 用户想定位自己的知识断层在哪里

---

## 核心概念界定

本技能中的概念分为两类，在输出中必须标注区分：

### 核心概念（type: "core"）

**定义**：理解目标概念原理所**必须**掌握的概念——如果缺失这个概念，就**无法完整理解**目标概念的核心工作方式。少一个都不行。

识别标准：
- 该概念直接参与目标概念的核心机制的构成或推导
- 删掉它会导致理解链断裂、无法自洽
- 该概念不是「了解更好」而是「不懂就卡住」

示例（目标 = 大语言模型原理）：
- Transformer 架构 ← 必须，这是 LLM 的骨架，不懂就没法往下
- 注意力机制 ← 必须，Transformer 的核心就是它
- 损失函数 ← 必须，不懂损失函数就无法理解模型怎么训练的
- 梯度下降 ← 必须，不懂怎么优化就无法理解训练过程

### 分支概念（type: "branch"）

**定义**：对该概念的理解起辅助作用，让认知更完整或更深入，但**不是理解目标概念原理的硬性前提**。属于「锦上添花」而非「雪中送炭」。

识别标准：
- 它的缺失不会导致核心理解链断裂
- 它通常是被核心概念引出、而非反向构成核心概念
- 它更多服务于「工程落地」或「完整知识面」而非「理解原理」

示例（目标 = 大语言模型原理）：
- 卷积神经网络（CNN）← 了解有帮助，但不是理解 LLM 的前提
- Dropout 正则化细节 ← 正则思路有用，但具体技术不是 LLM 核心

### 判断铁律

如果在拆解时犹豫一个概念是核心还是分支，用此方法判定：

> **如果把这个概念从知识体系里删掉，用户还能不能大致理解目标概念的核心原理？**
> 
> 能 → 分支 &nbsp;&nbsp;|&nbsp;&nbsp; 不能 → 核心

### 概念命名规范

节点名必须是**抽象名词或名词短语**，代表一个可独立存在的知识体系。禁止使用动词、动作描述、策略或流程作为节点名。

| 好 ✅（概念） | 坏 ❌（过程 / 动作） | 问题 |
|"MFCC（梅尔倒谱系数）" | "MFCC 特征提取" | 「提取」是动作，MFCC 本身才是概念 |
|"前馈神经网络" | "前馈网络与反向传播" | 「传播」是过程，网络结构才是概念 |
|"自回归语言模型" | "自回归预训练" | 「训练」是过程，语言模型才是概念 |
|"低资源语音数据" | "方言数据采集与标注" | 「采集」「标注」是动作，数据资源才是概念 |
|"多方言语音模型" | "多方言建模策略" | 「策略」不是概念，模型架构才是 |
|"指令调优" | "指令微调训练" | 去掉动词「训练」，保留名词「指令调优」 |

判断铁律：

> **去掉节点名里的动词，剩下的部分还能成为一个独立的知识点吗？**
>
> 能 → 去掉动词即可 &nbsp;&nbsp;|&nbsp;&nbsp; 不能 → 这不是一个概念，需要重新抽象

### 概念颗粒度原则

每个概念必须足够**细粒度**——细到一个具体的、可辨识的知识单元，而不是一整个学科课程。锚定层（用户已掌握的起点层）尤其容易犯「用学科名替代概念」的错误。

判断标准：
- 这个概念能否在**一个下午**内学懂核心要点？不能 → 太粗，需要拆分
- 这个概念是否直接服务于目标概念的某个具体子机制？不是 → 太泛，需要聚焦

| 目标概念 | 太粗 ❌（学科名） | 合适 ✅（知识单元） |
|"大语言模型" | "线性代数" | "矩阵乘法与转置"、"特征值与 SVD"
|"大语言模型" | "概率论与统计" | "条件概率与贝叶斯定理"、"信息熵与交叉熵"
|"大语言模型" | "微积分" | "链式法则"、"梯度与方向导数"
|"方言语音识别" | "微积分" | "链式法则"、"积分变换与傅里叶级数"

核心原则：**越是底层锚定概念，越要细化到直接参与依赖链的知识原子级别。** 不能让用户对着「线性代数」四个字去想「我需要重学整本教材吗」。

## 输入参数

### 必选
| 参数 | 类型 | 说明 |
|------|------|------|
| `target_concept` | string | 用户希望完全掌握的目标概念 |
| `current_level` | string | 用户当前的知识起点，描述为学历/已掌握的核心概念/当前学习阶段 |

### 可选
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `domain` | string | 自动识别 | 知识领域（计算机科学、物理学、经济学等） |
| `detail_level` | string | `标准` | 概念颗粒度：`精简` / `标准` / `详细` |
| `layer_hint` | number | 自动判定 | 期望层级数，仅供参考，最终以实际拆解为准 |

## 执行工作流

### 第 1 步：跨度评估

1. 识别目标概念所属的知识领域
2. 评估目标概念的抽象高度——是入门级、中级、还是前沿高度综合的概念
3. 评估用户当前所处的抽象位置
4. 估算语义跨度——起点到目标之间大约跨越几个认知台阶

### 第 2 步：动态构建层级体系

1. 根据语义跨度动态确定层级数 N（通常 3-8 层）
2. 为每层命名并定位——从底层到顶层体现抽象逐级递升：
   - **底层**：贴近用户已有的具象经验或已掌握知识
   - **中层**：领域通用的方法、工具、理论
   - **高层**：细分方向的专业理论、架构、技术
   - **顶层**：目标概念所在的高度综合层级
3. 给每层分配抽象星级（★，层数越多星数越密）
4. 起点层即为拆解底部边界——用户已掌握的不再向下拆

### 第 3 步：逆向依赖拆解

1. 从目标概念向下逐层拆解**直接前置依赖概念**
2. 遵循「单一高层概念 = 多个低层概念的抽象打包」原则
3. 每层只保留理解上层所必需的**核心概念**，其余标记为分支
4. 持续向下拆解，直到所有前置概念均落在用户起点层级及以下
5. 严格按照「核心概念界定」中的判断标准标注每个概念的类型

### 第 4 步：关系标注

1. 将概念按抽象程度从低到高分层
2. 为每层标注：层级编号、定位、抽象星级、概念列表
3. 梳理跨层依赖连线，区分**核心主干依赖**与**分支支撑依赖**
4. 标记**范式跃迁节点**——即认知模式发生本质变化的层级

### 第 5 步：生成 HTML 报告

生成自包含 HTML 文件到工作目录。HTML 必须零外部文件依赖（仅 dagre + d3.js CDN）。

HTML 结构遵循 `references/template.html`，包含以下区块：
- 头部信息（概念名、领域、层级数、起点、日期）
- 整体概览（层级跨度、核心主线、范式跃迁）
- 工具栏（搜索、重置、PNG 导出）
- **dagre 分层拓扑图**（见下方可视化规范）
- **概念速查表**（每个概念含「要解决的问题」「前置依赖」两列）
- 图例
- 分层详解卡片（可折叠，含学习建议）

模板变量：
| 占位符 | 替换内容 |
|--------|----------|
| `{{TARGET_CONCEPT}}` | 目标概念名称 |
| `{{DOMAIN}}` | 知识领域 |
| `{{LAYER_COUNT}}` | 层级数 |
| `{{START_LEVEL}}` | 起点描述 |
| `{{GENERATE_DATE}}` | 生成日期 |
| `{{OVERVIEW_TEXT}}` | 整体概览段落 |
| `{{MAIN_LINE}}` | 核心依赖主线 |
| `{{PARADIGM_BADGES}}` | 范式跃迁标签 HTML |
| `{{GRAPH_DATA}}` | JSON 格式 `{nodes: [...], links: [...]}` |
| `{{CONCEPT_TABLE_ROWS}}` | 概念速查表行 HTML |
| `{{LAYER_CARDS}}` | 分层详解卡片 HTML |

### 概念 `desc` 字段规范

每个节点的 `desc` 必须是一句**口语化、从解决问题视角出发**的解释（非教科书定义）。

| 好 ✅ | 坏 ❌ |
|--------|--------|
| "沿着损失函数的斜坡往下走，一步步把参数调到最优位置" | "梯度下降是一种迭代优化算法，用于找到函数的局部最小值" |
| "给每层加一个非线性开关，不然无论堆多少层本质上都只是线性变换" | "激活函数引入非线性变换，使神经网络能够逼近任意复杂函数" |
| "解码时别只看一个压缩向量——去输入序列每个位置看一眼，加权取重要信息" | "注意力机制通过计算查询和键的相似度来加权聚合值向量" |

### 概念速查表结构

速查表按层级从低到高排列，每行一个概念，包含以下列：

| 列 | 说明 |
|----|------|
| 层级 | 层号 + 层级色点 |
| 概念 | 概念中文名 |
| 类型 | 核心 / 分支（带色标） |
| 要解决的问题 | 一句话说清这个概念的**存在意义**——在前置概念打好的地基上，它解决了什么新问题 |
| 前置依赖 | 列出理解这个概念**必须已掌握**的下层或同层概念名（用 `→` 连接），没有则写「—」 |

范式跃迁节点的行用黄色底色标记。

## dagre 分层拓扑图规范

使用 **dagre**（Sugiyama 分层布局算法）计算节点位置，**d3** 负责渲染。

### 布局配置

```javascript
const g = new dagre.graphlib.Graph();
g.setGraph({
  rankdir: "BT",        // 从下到上：L1 在底部，L5 在顶部
  nodesep: 60,          // 节点水平间距
  ranksep: 85,          // 层级垂直间距
  marginx: 30,
  marginy: 20,
});
```

### 配色方案

层级配色（从低到高，暖色→冷色）：
```
L1: #FF6B6B  L2: #FFA94D  L3: #FFD43B  L4: #69DB7C  L5: #4DABF7
L6: #748FFC  L7: #9775FA  L8: #DA77F2
```

连线：
- 核心主干：`#495057`，线宽 2
- 分支支撑：`#ADB5BD`，线宽 1.2

### 交互功能

| 功能 | 实现 |
|------|------|
| 缩放 & 平移 | `d3.zoom()` 绑定到 SVG |
| 悬停提示 | tooltip div 显示概念名、层级、类型、解释 |
| 搜索 & 居中 | 输入框 + 按钮，找到节点后高亮路径并居中 |
| 路径高亮 | 点击节点 → BFS 上游+下游 → 无关节点变暗 |
| 全屏查看 | 按钮切换，图区铺满视口，ESC 或关闭按钮退出 |
| 重置视图 | 按钮恢复默认缩放与清除高亮 |
| 导出 PNG | Canvas 方式 SVG → PNG |

## 核心拆解原则

1. **不可跳级**：每个高层概念必须有直接下层概念支撑，禁止跨层悬空依赖
2. **最小必要**：只保留理解目标核心原理所必需的概念，不扩展无关旁支
3. **抽象递增**：每上升一层，概念的抽象程度和覆盖范围严格提升
4. **多源汇聚**：高层概念往往依赖多个不同维度下层概念共同支撑
5. **双向可解**：既能从下往上归纳出高层概念，也能从上往下拆解为低层细节

## 输出

执行完成后：
1. 将 HTML 文件写入当前工作目录
2. 调用 `present_files` 展示 HTML 文件
3. 在对话中给出 1-2 段简明总结，不重复 HTML 中已有的详细内容

## 异常处理

- 用户当前层级描述模糊 → 主动询问已掌握的核心概念，明确起点后再拆
- 目标概念过于小众 → 先与用户确认概念内涵和边界
- 目标层级低于当前层级 → 说明情况，提供向下拆解 + 向上延伸双向路径
- 跨领域概念 → 拆分不同领域依赖分支分别呈现
- 节点数超过 200 → 增加节点聚类/折叠功能

## 边界说明

1. 本技能聚焦概念层级与依赖关系梳理，不替代具体知识点的深度讲解
2. 人文社科等非结构化领域的层级划分会适配调整，侧重逻辑递进关系
3. 概念筛选以「理解核心原理」为标准，需要工程落地级完整知识可提高 `detail_level`
4. 不处理用户提供的学习材料、书单、课程链接等资源输入
