# 发布前内容合规审查（默认开启）

投稿前必须对成片字幕做一次合规审查。审查由 Agent（模型）执行，脚本只负责
「准备 transcript → 解析结果 → 裁剪 → 门禁校验」。

- 审查提示词：本文「提示词」一节，**整段照抄**，只替换 `{{transcript}}`。
- 审查产物：`review.json`（人工可读 + `trim_video.py` 可解析）。
- 门禁产物：`<video>.compliance.json`（由 `trim_video.py` 写出，`bilibili_push.py --compliance on` 强制校验）。

---

## 1. 开关语义

| 场景 | 行为 |
|---|---|
| 默认（用户没提） | **开启审查** |
| 用户说「跳过审查」「不用审查」「直接发」 | 关闭，`--compliance off`，日志必须标注「⚠ 未审查」 |
| `tasks.json` 单条 `"compliance": false` | 仅该条关闭，其余仍审 |

关闭审查是用户的显式决定，**不得**由 Agent 自行判断「这条应该没问题」而关闭。

---

## 2. 步骤

### 2.1 取字幕（必须有时间轴）

优先级：

1. bmx 服务端成片字幕（与配音视频同 basename）：
   ```bash
   SERVER=$(python3 -c "import json;print(json.load(open('$HOME/.bilimix/config.json'))['server'])")
   BASE=<bmx task result 里的 basename>
   curl -L -o "downloads/<任务名>.ass" "${SERVER}/api/audio/${BASE}/${BASE}.ass"
   ```
2. 本地已有的 `.ass` / `.srt`（例如 `nows-video-bmxcut` 的 `outputs/subtitles.ass`）。

**两条都拿不到 → 停下来问用户**：提供字幕文件，或明确同意关闭审查。
不允许「没字幕就当通过」。

### 2.2 生成 transcript

```bash
python ~/.workbuddy/skills/nows-bilibili-push/scripts/ass_to_transcript.py \
    --sub "downloads/<任务名>.ass" --chunk-min 20
```

产物（与字幕同目录，或 `-o` 指定）：

- `transcript.json`：结构化片段（`start`/`end` 秒），供裁剪对齐整句
- `transcript.txt`：整篇 `[HH:MM:SS] 中文` 文本
- `transcript.partNN.txt`：长视频分块（默认 20 分钟/块，块间 2 分钟重叠）

脚本会打印「中文行占比」。占比过低说明拿到的不是中文成片字幕，
审查结论不可信 → 找用户确认字幕来源。

### 2.3 执行审查

- 字幕行数 ≤ ~1200 行：直接把 `transcript.txt` 塞进提示词一次审完。
- 更长：**逐块**审 `transcript.partNN.txt`，块间重叠区结论取并集（同一时间戳只保留一条）。
  不要为了省事只审开头。

审查后写 `review.json`（见第 3 节），并用一段话向用户汇报发现。

### 2.4 裁剪

```bash
python ~/.workbuddy/skills/nows-bilibili-push/scripts/trim_video.py \
    --video "downloads/<任务名>.mp4" \
    --review "downloads/<任务名>.review.json" \
    --transcript "downloads/transcript.json"
```

- 无 `cut` 项 → 只写 `result: pass` 的门禁文件，视频不动。
- 有 `cut` 项 → 输出 `<任务名>.trimmed.mp4` 并写 `result: trimmed`。
- 触发阻断（时长损失 > 20% 或 删 > 3 段）→ 写 `result: blocked`，**该条不上传**，
  报告用户；用户坚持要发需自己给 `--force`。
- 先看计划不加 `--dry-run`？给用户确认时用 `--dry-run` 打印裁剪表，确认后再实跑。

**裁剪后必须人工（Agent）复核一遍**：新视频时长、剩余内容是否还成立、
简介/封面/标题是否引用了被删内容（引用到了就改文案，不要发一个和标题不符的视频）。

### 2.5 投稿门禁

`bilibili_push.py --compliance on`（默认）会逐条检查 `<video>.compliance.json`：

- `reviewed: true` 且 `result: pass | trimmed`
- `result: trimmed` 时，门禁文件里的 `video` 必须等于 `tasks.json` 里要上传的 `video`
  （防止审查说要裁、实际还是传了原片）

门禁文件位置 = **实际要上传的那个文件** 的路径 + `.compliance.json`：

| 结果 | 门禁文件 |
|---|---|
| `pass` | `<原视频>.mp4.compliance.json`（`video` = 原视频） |
| `trimmed` | `<原视频>.trimmed.mp4.compliance.json`（`video` = 裁剪产物） |
| `blocked` | 写在计划输出路径旁，`video: null`，投稿脚本必然拒绝 |

任一不满足 → **启动浏览器前就整体退出**，打印修复方法。不要试图改文件名绕门禁。

## 3. review.json 格式

```json
{
  "video": "/abs/downloads/xxx.mp4",
  "reviewed_at": "2026-10-20T10:00:00",
  "issues": [
    {
      "start": 1234.5,
      "end": 1268.0,
      "level": "明确风险",
      "action": "cut",
      "reason": "具体说明风险及判断依据",
      "suggestion": "最小修改建议 / 无法忠实修改",
      "quote": "原始中文片段"
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `start` / `end` | **秒**（浮点），必须给区间，不能只给起始时间戳 |
| `level` | `疑似风险` / `明确风险` |
| `action` | `cut` = 裁剪该区间；`block` = 整条不建议发布；`review` = 保留 + 人工核实 |

映射规则（与提示词「处理规则」一致）：

- 无风险 → 不写 `issues`（空数组），`result` 自然为 `pass`
- 疑似风险 → `action: "review"`，**默认保留不裁**，在汇报里列出来
- 明确风险 + 能最小修改 → 仍写 `action: "review"`，建议改文案；**不改字幕、不裁画面**
- 明确风险 + 无法忠实修改但可整段删除 → `action: "cut"`
- 删了会导致内容不成立 → `action: "block"`

`action` 出现拼写错误会被当 `review` 忽略，裁剪前请 `--dry-run` 核对区间数量。

---

## 4. 裁剪规则（脚本已实现，了解即可）

1. **对齐整句**：给了 `--transcript` 时，裁剪区间扩展到覆盖所有与之相交的整句，
   不会切在半句话中间。
2. **安全缓冲**：前后各外扩 0.4s / 0.5s（`--pad-before` / `--pad-after`）。
3. **关键帧外扩（默认 `--mode keyframe`）**：保留段起点向上取整到关键帧、
   终点向下取整到关键帧 —— **只多切，不残留**。全程 `-c copy`，速度快。
4. **自动回退**：关键帧间隔 > 4s 或 copy 失败 → 自动改用 `libx264` 重编码，
   帧级精确但慢（长视频可能几十分钟）。
5. **校验**：输出时长与保留段之和偏差 > 5s 视为失败，不写 `pass/trimmed`。

## 5. 提示词

````text
# 角色：中文内容合规审查专家

你负责审查海外 AI、科技、商业类播客的视频字幕，评估其在中国大陆视频平台（B站、抖音等）发布时可能存在的内容合规风险。

## 核心原则

1. **只审查合规性**：不进行翻译校对、语言润色、风格调整或内容优化。
2. **保持原意**：不得改变原文的事实、观点、立场、语气及核心信息。
3. **最小干预**：没有明确合规风险的内容，一律不修改。
4. **上下文判断**：不能仅凭敏感词判定违规，必须结合完整语境。
5. **不规避审核**：不使用谐音、拼音、错别字、符号替换等方式绕过平台审核。
6. **不虚构规则**：无法确定是否违规时，标记为人工复核，不得声称一定违规或一定通过审核。

## 审查范围

仅检查以下可能涉及内容合规的问题：

- 违反中国大陆现行法律法规或平台公开内容规范的信息。
- 煽动仇恨、歧视、暴力及违法行为的内容。
- 可能构成严重不实信息、诽谤或侵犯他人合法权益的内容。
- 涉及国家安全、公共安全等需要特别审查的具体表达。
- 其他存在明确依据的内容发布风险。

正常的 AI 技术讨论、商业竞争、国际科技新闻、政策分析、企业评价及学术研究，不得仅因包含敏感话题或词汇而认定违规。

## 处理规则

- **无风险**：保留原文，不输出。
- **疑似风险**：指出具体原因及需要核实的事项，交由人工复核。
- **明确风险**：指出对应内容及依据；如果能够在不改变原意的前提下合规修订，则提供最小修改建议。
- **无法忠实修改**：不强行改写，建议人工决定是否发布该片段。

不得通过弱化、删除或篡改嘉宾观点来制造表面合规的内容。

## 输出格式

仅输出存在合规疑虑的片段：

**时间戳：**

**原始中文：**

**风险等级：** 疑似风险 / 明确风险

**风险原因：** 具体说明风险及判断依据。

**处理建议：** 保留并核实 / 最小修改 / 人工决定是否发布

**建议修改：** 仅在必要且不改变原意时提供，否则填写“无需修改”或“无法忠实修改”。

如果没有发现合规风险，仅输出：

“未发现明确的内容合规风险，无需修改。”

注意：审查结论不等于平台审核保证。

## 待审查内容
{{transcript}}
````

### 5.1 追加输出要求（每次审查都要加在提示词末尾）

```text
## 额外输出要求（机器可读）

在自然的审查说明之后，追加一个 JSON 代码块，供自动化裁剪使用：

```json
{
  "issues": [
    {
      "start": 1234.5,
      "end": 1268.0,
      "level": "疑似风险 | 明确风险",
      "action": "review | cut | block",
      "reason": "判断依据（中文，一句话以上）",
      "suggestion": "最小修改建议 / 无法忠实修改 / 无需修改",
      "quote": "对应原始中文字幕（可截断）"
    }
  ]
}
```

约束：

- `start` / `end` 是从 transcript 行首 `[HH:MM:SS]` 换算出的**秒**，必须是区间。
- 只有「明确风险」且**整段删除不会破坏上下文**时才可给 `action: "cut"`。
- 疑似风险一律 `action: "review"`，不要裁。
- 无风险时输出 `{"issues": []}`。
- JSON 之外不要再输出别的内容，JSON 必须能被 json 解析。
```
