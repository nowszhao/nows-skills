# 方法依据、调参与排错

本文件记录 `scripts/ytb2pdf.py` 各阈值**为什么这样设**，以及遇到非标准视频时怎么改。遇到拿不准的画面类型先读这里，不要凭直觉改参数。

## 1. 为什么不能按固定间隔抽帧

「每 N 秒截一张」同时违反三条要求：页面停留时长不固定（10～40 秒都有可能）→ 短页被漏掉、长页被抽多次；切换瞬间会截到转场混合帧；无法证明覆盖完整。

正确做法是把全片按**画面稳定段**切开：只在画面发生硬切时产生新页，每段只取一张代表帧。静止视频的帧间差异绝大多数是精确 0，这让切段几乎不会出错。

## 2. 算法链条与阈值来源

| 步骤 | 做法 | 默认值 | 依据 |
|---|---|---|---|
| 抽帧 | ffmpeg 流式输出 2 fps、320×180 灰度 rawvideo 到 numpy | `--fps 2` | 幻灯片最短停留通常 >5 秒；2 fps 足以捕获切换，又不至于让 1 小时视频占满内存 |
| 掩膜 | 屏蔽顶部 16 行、右下 x≥0.86 且 y≥0.76 | `--mask-top-px 16`、`--pip-x/y` | 章节进度条与摄像头画中画会动，不屏蔽会被误判成几十次「新页面」 |
| 切换判定 | 掩膜后相邻帧平均绝对差 MAD > 1.0 | `--switch-threshold` | 实战：静止帧 MAD ≈ 0.00～0.09，噪声 0.2～1.1，真实硬切 10～53，分界非常干净 |
| 事件合并 | 相隔 ≤3 个采样帧的变化合并为一次切换 | `--merge-gap 3` | 淡入淡出/转场余波会连续 1～2 帧有差异 |
| 代表帧 | 取稳定段的**时间中位帧** | — | 段首尾可能残留转场帧，中位帧最稳 |
| 段内核验 | 段内所有帧与代表帧的 MAD；仅当段中段出现 > `max(1.5, thr×1.5)` 才告警 | 内置 | 摄像头淡入、光标、字幕闪烁约 0.5～1.1；段首 2 秒内的尖峰判为转场余波，不告警 |
| 空白页 | 掩膜后对比度 std < 2.0 判为黑屏/纯色页 | `--blank-std` | 深色主题幻灯片 std 约 27～35，不会被误删 |
| 跨段去重 | 先用 1/4 降采样做全对粗筛，再对候选对算全尺寸 MAD；< 3.0 合并，保留首次出现 | `--dup-threshold` | 避免 O(n²) 全尺寸计算；3.0 远小于真实页面间差异（实战最小 6.36），只会合并几乎完全相同的页 |
| 导出 | 按代表帧时间回原视频抽 1920×1080 JPEG（q2），无损嵌入 PDF，页面比例随源 | `--page-size auto` | 不重新压缩、不裁切；960pt 宽对应 1920px @144dpi |

**「不重复」的证据**是 `report.json` 的 `min_coarse_pair_distance`：它应显著大于 `--dup-threshold`。若接近阈值，说明有两页内容很像，打开 HTML 核对表目视比对，再决定调低阈值或保留两页。

**「不遗漏」的证据**是三个数字对得上：`switch_events + 1 == segments_total`，`segments_total == final_pages + 空白页数 + 重复页数`，且 `segments_with_internal_motion` 为空。

## 3. 实战基准（可用来判断新视频是否异常）

视频：`youtube.com/watch?v=oeknLUsN_GE`，AI Engineer 演讲，18:03，1920×1080 AV1，只要画面轨 17 MB。

- 采样 2166 帧（125 MB 内存）；90% 以上相邻帧差异为 0。
- 50 次硬切 → 51 个稳定段 → 51 个唯一页面；无空白页、无重复页。
- 全尺寸代表帧最相似距离 6.36（脚本的 coarse 版本 7.18），远大于去重阈值 3.0。
- 段内最大 MAD：绝大多数 < 0.1；摄像头/光标噪声 0.687～1.068；段首转场余波 3.493（已被 afterglow 规则豁免）。
- 输出：51 页 PDF，960×540 pt，每页 1920×1080，约 8 MB；端到端约 60～90 秒。

若新视频出现「几百次切换」或「页均停留 < 3 秒」，基本可以判定是掩膜没覆盖到动态叠加层，或视频不是静态幻灯片，先按第 4 节排查。

## 4. 画面类型适配表

| 情况 | 现象 | 处理 |
|---|---|---|
| 静态 PPT / 硬切（默认） | 切换数 ≈ 页数-1，段内 MAD ≈ 0 | 直接用默认参数 |
| 渐进动画（元素逐个出现） | 同页被拆成多段，`internal_suspicious` 告警 | 先看 HTML 核对表；若确实是同一页的不同阶段，只保留信息最全的一张（手工删页）或适当提高 `--switch-threshold` 至 2～3 后重跑，并复核 |
| 淡入淡出 / 长转场 | 切换数偏多、出现半透明混合页 | `--merge-gap 5`～`8`；必要时提高 `--switch-threshold` |
| 烧录字幕 | 每次字幕变化都被当作新页 | `--mask-bottom-px 20`（约底部 11%），字幕在更上方时加大 |
| 摄像头画中画不在右下角 | 切换数异常多 | 改 `--pip-x` / `--pip-y` 指向实际区域；纯色边框可用 `--no-mask` 配合更高 `--switch-threshold` 试验 |
| 网页滚动 / 实时演示录屏 | 页数爆炸 | 本 skill 不适用「每一页」语义；先与用户确认范围，或只截取指定时间段、把 `--switch-threshold` 提到 3～5 |
| 片头黑屏、片尾纯色页 | 被判为空白页剔除 | 若用户要保留，加 `--keep-blank` |
| 低对比度纯色内容页 | 可能被 `--blank-std` 误删 | 加 `--keep-blank`，或降低 `--blank-std` 至 1.0 |
| 非 16:9 视频 | — | 脚本按源比例自动计算 PDF 页面尺寸，`--sample-width` 只控制分析帧宽 |

## 5. 调参流程

1. 先跑 `python3 ytb2pdf.py <源> --dry-run --out-dir /tmp/probe`，只产出 `report.json`，几秒到几十秒。
2. 看 `switch_events`、`segments_total`、`pages[].dur`、`min_coarse_pair_distance`、`warnings`、`segments_with_internal_motion`。
3. 按第 4 节改一个参数，重跑 dry-run 对比，**一次只改一个**。
4. 数字合理后再跑完整命令生成 PDF 与核对表。
5. 交付前按第 8 节清单核验。

不要用 `--max-seconds` 做正式交付；它只用于快速试参数，会破坏「不遗漏」。

## 6. YouTube 反爬排错

- 典型报错：`Sign in to confirm you're not a bot`。原因是数据中心 IP 被判定为机器人，**换 `player_client` 通常无效**（`tv` / `ios` / `android_vr` 实测同样被拦）。
- 有效解法：`yt-dlp --cookies-from-browser chrome`。脚本会依次尝试 chrome、edge、firefox、brave、safari，成功后记录所用浏览器到 `report.json`。
- `safari` 在 macOS 上常报 `Operation not permitted: Cookies.binarycookies`，需要「完全磁盘访问权限」；不必为此中断，其他浏览器够用。
- 若所有浏览器都失败，先让用户在对应浏览器登录一次 YouTube 并确认 cookies 未过期，再重试；不要伪造登录态、不要改用非官方镜像站点。
- `yt-dlp` 保持较新版本（2026-08 版实测可用）；过旧版本解析不了新的播放器响应。
- 只下载画面轨（`-f bestvideo[height<=1080]...`）：本任务不需要音频，18 分钟 1080p 仅约 17 MB。
- URL 模式的视频元数据（标题/频道/时长）也走同一 cookies；若取不到，脚本退化为用视频 ID 作 PDF 标题，可用 `--title` 覆盖。

## 7. 性能与规模

- 内存：320×180 灰度、2 fps ≈ 0.115 MB/秒，18 分钟约 125 MB，1 小时约 415 MB。超过 800 MB 时脚本会警告，长视频改用 `--fps 1`（切换检测仍足够，只是时间精度 ±1 秒）。
- 耗时主要在两段：ffmpeg 全片解码抽帧、按 51 个时间点精确 seek 抽全分辨率静帧。1080p / 18 分钟端到端约 1 分钟。
- 下载的临时视频默认在结束时删除，`--keep-video` 保留，`--reuse-video` 复用；本地 `--video` 输入**永不修改或删除**。

## 8. 交付前核验清单

- `report.json`：`verification.checked == true` 且 `page_count_matches == true`。
- `verification.first_page_image_px` 等于源视频分辨率；页面尺寸比例与源一致。
- `warnings` 为空；不为空时按提示抽帧人工复核，并在回复中如实说明。
- `min_coarse_pair_distance` 显著大于 `dup_threshold`；`duplicates_removed` 与 `blank_removed` 符合预期。
- 打开 `页面核对表.html` 抽检首、中、末页及最相似的一对，确认没有黑屏、转场残影、重复页，且画面四边完整。
- 用文件呈现能力交付 PDF 与核对表，回复里给出页数与核验结论。

## 9. 已知边界

- 不做 OCR、不生成页面说明、不重排页面顺序。
- 默认保留摄像头/进度条等叠加层；裁剪属于额外需求。
- 渐进式动画与滚动画面无法在「全自动」前提下完美合并，脚本会告警并交由人工判断，绝不静默猜。
- 去重保留**首次出现**的页面；若后一次出现更完整（例如摄像头消失），需人工替换 `pages_full/` 中对应图片后重新生成 PDF。
